# Gateway SDK 模块使用指南

适用版本：`agent-gateway-client 0.2.0`。本文以当前 SDK 代码为准。

SDK 是异步 Python 客户端，不是服务端。其他业务项目无需访问 Knowledge 数据库，即可通过 Gateway 读取向量、父块、用户画像和长期记忆。业务项目仍负责登录验证、权限、文档解析、切片、版本管理和后台任务。

## 1. 安装与配置

要求 Python 3.11 或以上。开发时，在业务项目后端执行：

```powershell
uv add --editable ../../gateway_api
```

相对路径按实际目录调整；Knowledge 的 `backend` 与 SDK 仓库之间就是该路径。生产环境建议安装构建的 wheel，或固定 Git 提交/标签，并提交业务项目的 `uv.lock`。

```powershell
# 在 gateway_api 中构建
uv build
# 在业务项目中安装，路径按实际位置调整
uv add ../../gateway_api/dist/agent_gateway_client-0.2.0-py3-none-any.whl
```

SDK 不读取 `.env`。以下环境变量只是业务项目的配置约定，由业务后端读取并传入 SDK：

```dotenv
GATEWAY_VECTOR_BASE_URL=http://127.0.0.1:8080/gateway/v1
GATEWAY_VECTOR_API_KEY=replace-with-server-side-project-key
GATEWAY_VECTOR_COLLECTION=my-knowledge
GATEWAY_EMBEDDING_MODEL=volc/doubao-embedding-vision
```

```python
import os
from gateway_client import GatewayClient

client = GatewayClient(
    base_url=os.environ["GATEWAY_VECTOR_BASE_URL"],
    api_key=os.environ["GATEWAY_VECTOR_API_KEY"],
    collection=os.environ["GATEWAY_VECTOR_COLLECTION"],
    embedding_model=os.environ["GATEWAY_EMBEDDING_MODEL"],
)
```

| 构造参数 | 含义 | 默认值 |
|---|---|---|
| `base_url` | Gateway 地址，包括实际代理前缀 | 必填 |
| `api_key` | 服务端持有的 Gateway 项目 Key | 必填 |
| `collection` | 向量集合名称，只用上下文模块可省略 | 空字符串 |
| `embedding_model` | 创建集合使用的完整模型名 | 空字符串 |
| `vector_base_url` | 向量服务使用另一地址时指定 | `base_url` |
| `vector_timeout` | 向量请求超时秒数，每次请求的限制 | 120 |
| `context_timeout` | 上下文请求超时秒数 | 15 |
| `transport` | 注入 `httpx` 传输，主要用于测试 | `None` |

地址末尾未包含 `/v1` 时 SDK 会补齐；不要传 Swagger 的 `/docs` 地址。模型名原样传递，SDK 不添加或去掉 `volc/` 等前缀。现有集合的模型和维度由 Gateway 固定，不能通过修改客户端参数改变。

所有业务调用都需要 `await`。在 FastAPI 等异步服务内直接调用；脚本使用 `asyncio.run(main())`。同一 SDK 实例的地址、Key 和集合应保持固定，不要在并发请求中修改属性来切换用户或集合。

## 2. 模块边界

```text
gateway_client/
├── client.py        GatewayClient：统一入口，组合 vectors 和 context
├── vector_store.py  GatewayVectorStore：集合、记录写入/读取、发布、检索、删除
├── context.py       GatewayContextClient：画像、长期记忆、会话消息读取/清空
├── transport.py     GatewayTransport：HTTP、Bearer 认证、超时、Trace ID
├── errors.py        两类能力异常及安全错误字段
└── __init__.py      对外导出
```

一般使用 `GatewayClient`。只需要一种能力，也可以直接创建 `GatewayVectorStore` 或 `GatewayContextClient`。迁移时安装整个包；不要只复制单个文件，因为模块之间存在相对导入。运行依赖只有 `httpx` 和 Python 标准库，不依赖 FastAPI、SQLAlchemy、LangChain 或身份中心。

同一个 `GatewayClient` 的两个模块使用同一 Key。向量和上下文需要不同 Key 时，创建两个客户端。

## 3. 向量模块：普通切片检索

### 集合选择与创建

```python
collections = await client.vectors.list_collections()
# 已有集合：选定名称后构造对应客户端即可，不必再次创建。
# 新建集合：模型从构造参数读取，也可以显式传 model。
collection = await client.create_collection(
    description="业务知识库", chunk_size=1000,
)
```

`create_collection` 会先查集合；已存在时验证模型及 `chunk_size` 是否一致，不会修改已有配置。创建时 Gateway 的 `chunk_overlap` 固定传 0，因为业务项目已经切片。集合的 `chunk_size` 也是单条向量文本的长度上限。

### 写入与检索

```python
await client.add_vectors([
    {
        "id": "manual-001-part-0001",
        "content": "申请退款需要提供订单号。",
        "metadata": {
            "app_id": "support-app", "record_type": "knowledge_chunk",
            "source": "手册/退款.md", "category": "售后", "part": 1,
        },
    },
])

hits = await client.similarity_search(
    "退款需要什么资料？", k=5,
    metadata={"app_id": "support-app", "record_type": "knowledge_chunk"},
)
for hit in hits:
    text, score, metadata = hit["content"], hit["score"], hit.get("metadata", {})

await client.delete_vectors(["manual-001-part-0001"])
```

SDK 不切片，也不调用独立的 Embedding 接口；它将预切片文本提交给 Gateway，由 Gateway 生成并保存向量。`metadata` 是 JSON 包含匹配，检索只返回可见的向量记录。

写入每批最多 64 条，同时控制请求体不超过 4 MiB；SDK 会自动分批。向量正文最多 6000 字符，且必须满足集合 `chunk_size`。ID 非空、最多 200 字符，一次输入不得重复。查询文本最多 10000 字符，`k` 范围为 1～20。

删除使用外部 ID，按 256 个一批；返回聚合的 `deleted`、`deleted_ids`、`missing_ids`。正常文档更新只清理旧记录，不删除集合。SDK 尚未提供公开的集合删除方法。

## 4. 父子层级：写入与版本发布

父块保存完整上下文，不进行向量化；子块保存短文本，参与向量检索。二者在同一集合中通过顶层 `parent_id` 关联。切片及父块 ID 由业务项目生成。

```python
from uuid import uuid4

# 示例：实际业务应把 version_id、父子 ID 和任务状态持久化。
# 新内容版本生成新 ID；同一次任务的重试复用原 ID。
version_id = uuid4().hex
namespace = "support-app:team-1"
document_id = "manual-001"
parent_id = f"{document_id}-{version_id}-parent-0001"
child_id = f"{document_id}-{version_id}-child-0001"
scope = {
    "namespace": namespace, "document_id": document_id,
    "version_id": version_id, "staged": True,
}
common_metadata = {
    "app_id": "support-app", "document_id": document_id,
    "source": "手册/退款.md", "category": "售后",
}

# 第一步：先写父块；普通记录最多 20000 字符。
await client.add_records([{
    "id": parent_id, "record_kind": "document",
    "content": "退款流程：提交订单号和支付凭证，客服审核后原路退回。",
    "metadata": {**common_metadata, "record_type": "knowledge_parent"},
    **scope,
}])

# 第二步：父块已存在后写子块，不能同批引用刚创建的父块。
await client.add_vectors([{
    "id": child_id, "record_kind": "vector", "parent_id": parent_id,
    "content": "申请退款需要订单号和支付凭证。",
    "metadata": {**common_metadata, "record_type": "knowledge_chunk"},
    **scope,
}])

# 第三步：全部确认写入后发布。此前 query/fetch 看不到暂存记录。
await client.publish_version(namespace, document_id, version_id)
```

`add_records` 可写普通或向量记录；`add_vectors` 只接受向量记录。`record_kind` 省略时为 `vector`。普通记录的正文放在 `content`，不要在每个子块 metadata 中重复父块正文。

新版本发布会隐藏相同 `namespace + document_id` 的旧版本。业务侧应在发布成功后先删除旧子块，再删除旧父块；它们的 ID 需要业务侧保存。发布不是物理清理，也不会隐藏未使用此版本范围的旧式记录。

发布超时可能已经生效：重试同一个版本，不要删除目标版本。已发布版本不允许改内容；内容回退到历史文本也必须生成新版本及新记录 ID。完全相同的发布重试返回 `already_published`。

无版本父子记录也支持：同时省略 `namespace/document_id/version_id/staged` 即可直接写入可见记录，但不会获得版本原子发布能力。生产文档更新推荐使用上述暂存发布流程。

## 5. 父子层级：其他项目如何读取

其他项目配置相同 Gateway 项目 Key 可访问的集合，不需要连接 Knowledge 数据库。

```python
hits = await client.similarity_search_with_context(
    "退款需要什么资料？", k=5,
    metadata={"app_id": "support-app", "record_type": "knowledge_chunk"},
)

contexts = []
seen_parents = set()
for hit in hits:
    # 命中位置及相似度仍保留在 content / score 中。
    # context_content 是给 LLM 的上下文；无父块时就是子块正文。
    parent_id = hit.get("parent_id")
    if hit["context_status"] == "available" and parent_id:
        if parent_id in seen_parents:
            continue
        seen_parents.add(parent_id)
    contexts.append(hit["context_content"])
```

此方法执行 `query → 去重父块 ID → 批量 fetch → 补充 context_content`。结果保留每条子块命中，不自动合并父块。

| 情况 | `context_content` | `context_status` |
|---|---|---|
| 有父块且取回普通记录 | 父块正文 | `available` |
| 普通切片，无 `parent_id` | 子块正文 | `available` |
| 父块缺失或类型不是 `document` | 子块正文 | `missing` |

`fetch` 请求失败时此方法抛异常，不自动降级。业务项目可以捕获后使用普通检索，或提示用户重试。

需要自己控制读取、缓存和去重时：

```python
hits = await client.similarity_search("退款资料", metadata={"category": "售后"})
ids = list(dict.fromkeys(h["parent_id"] for h in hits if h.get("parent_id")))
parents = await client.fetch_records(ids)
# parents = {"collection": ..., "records": [...], "missing_ids": [...]}
```

`fetch_records` 按 256 个 ID 分批，去重输入，并按请求顺序返回已找到的记录。这里及 `delete_vectors`、`parent_id` 都使用调用方 ID：写入响应的 `external_id`。upsert 响应的 `id` 是 Gateway 内部 UUID，不要混用。

Knowledge 写入的记录使用 `app_id=knowledge-platform`。读取它的子块应过滤 `record_type=knowledge_chunk`。个人数据再过滤对应的 `owner_user_id`；共享知识库应由后端根据权限确定允许的作者/共享范围，不要把“当前登录者 ID”机械地当成所有共享文档的作者 ID。

## 6. 上下文模块：用户画像

```python
# 必须来自本项目后端验证过的登录身份，不能直接信任浏览器提交值。
user_id = verified_user_id
await client.context.validate_user_access(user_id)

current = await client.context.get_profile(user_id)
updated = await client.context.put_profile(
    user_id,
    profile={**current["profile"], "language": "zh"},
    expected_version=current["version"],
)
```

画像返回 `profile` 和 `version`。写入使用读取到的版本进行并发控制；版本冲突应重新读取后让业务决定如何合并。SDK 不定义用户画像 Schema。

## 7. 上下文模块：长期记忆

```python
page = await client.context.list_memories(user_id, page=1, page_size=20)
items = page["items"]

created = await client.context.create_memory(
    user_id, content="用户偏好中文回答。",
    tags=["偏好"], metadata={"source": "conversation"},
)

# item 为列表/接口返回的当前记忆，包含 id 和 version。
if items:
    item = items[0]
    await client.context.update_memory(
        user_id, item["id"], expected_version=item["version"],
        content="用户偏好简洁的中文回答。", tags=["偏好"],
        metadata={"source": "conversation"},
    )
    # 删除前重新读取取得最新版本；不能继续用修改前的 version。
    latest = await client.context.list_memories(user_id, page=1, page_size=20)
    refreshed = next((m for m in latest["items"] if m["id"] == item["id"]), None)
    if refreshed:
        await client.context.delete_memory(user_id, refreshed["id"], refreshed["version"])
```

记忆更新和删除都要求版本；SDK 返回 Gateway 当前响应，不自行重新嵌入或选择记忆集合。记忆是否向量化、使用哪个集合，由 Gateway 的上下文服务契约与配置决定，不由 `client.vectors.collection` 控制。

## 8. 上下文模块：会话消息

```python
messages = await client.context.list_session_messages(user_id, session_id, limit=50)
for message in messages["messages"]:
    # 按业务需要处理 Gateway 返回的消息字段。
    pass

# 清空指定用户、指定会话的消息；执行前由业务校验删除权限。
await client.context.delete_session_messages(user_id, session_id)
```

当前 SDK **没有封装会话列表、会话创建、消息追加和长期记忆语义检索**。不要假设这些方法存在。`session_id` 由业务系统提供；需要新增能力时先核对 Gateway OpenAPI，再扩展适配器。

## 9. HTTP 与异常处理

传输模块统一添加 `Authorization: Bearer <key>`、JSON 请求头和 `X-Trace-ID`。每次请求创建并关闭 `httpx.AsyncClient`，不需要额外调用 SDK 的 `close`。`trust_env=False`，不会使用系统代理环境变量。

通常不直接使用 `GatewayTransport`；它不负责业务响应解析，也不主动把 HTTP 4xx/5xx 转成能力异常。

向量请求对网络异常、超时及 HTTP 502/503/504 最多重试两次；等待分别为 0.5 秒、1 秒。HTTP 500 和 429 不在自动重试范围。上下文请求没有自动重试，尤其写入时由业务结合版本控制决定重试方式。

```python
from gateway_client import GatewayVectorStoreError, GatewayContextError

try:
    await client.add_vectors(prepared_records)
except GatewayVectorStoreError as error:
    # 只记录安全字段，不记录 Key、请求正文或原始服务器响应。
    safe_error = {
        "code": error.code,
        "http_status": error.status_code,
        "trace_id": error.gateway_trace_id,
        "confirmed_ids": error.confirmed_ids,
        "uncertain_ids": error.uncertain_ids,
    }
    # confirmed_ids 是已确认的前序批次；uncertain_ids 是当前未确认批次。
    # 后续尚未发送的批次不在这两个列表中；任务状态由业务侧持久化。
    raise

try:
    profile = await client.context.get_profile(user_id)
except GatewayContextError as error:
    if error.code == "GATEWAY_CONTEXT_VERSION_CONFLICT":
        # 写入冲突时重新读取并处理合并，不盲目覆盖。
        pass
    raise
```

常见向量错误包括认证失败、额度不足、部分批次确认不完整、父块不存在、父块仍被引用、版本不可修改和发布历史未知。业务日志可记录稳定 `code/status_code/gateway_trace_id`，前端使用清晰的业务错误文案。

## 10. 身份、权限与业务职责

- API Key 决定 Gateway 项目和服务访问权限，不能代替终端用户登录认证。
- SDK 不自动注入 `app_id`、`record_type`、`owner_user_id` 等过滤条件。业务后端必须固定授权范围，防止前端任意覆盖。
- metadata 过滤是查询条件，不是 Gateway 独立的用户行级授权。按 ID 读取父块时仍要按业务需要校验返回记录的归属；便捷检索方法只检查父块类型，不校验作者。
- Key 只从服务端配置或安全存储取得，不发送到浏览器，不写日志。
- SDK 不包含本地数据库、切片器、版本 ID 持久化、任务队列、操作日志或身份中心客户端。这些由业务项目提供。

## 11. 方法速查

| 能力 | 方法 | Gateway 路由（均位于 `/v1` 下） |
|---|---|---|
| 列出集合 | `client.vectors.list_collections()` | `GET /vector-stores/collections` |
| 创建/验证集合 | `client.create_collection(...)` | 列表查询及必要时 `POST /vector-stores/collections` |
| 写向量/普通记录 | `client.add_vectors(...)` / `client.add_records(...)` | `POST /vector-stores/collections/{collection}/upsert` |
| 普通记录读取 | `client.fetch_records(ids)` | `POST .../{collection}/fetch` |
| 版本发布 | `client.publish_version(...)` | `POST .../{collection}/publish` |
| 向量检索 | `client.similarity_search(...)` | `POST .../{collection}/query` |
| 父子检索 | `client.similarity_search_with_context(...)` | `query` + `fetch` |
| 删除记录 | `client.delete_vectors(ids)` | `POST .../{collection}/delete` |
| 画像读写 | `context.get_profile` / `context.put_profile` | `GET/PUT /context/users/{user_id}/profile` |
| 记忆列表/创建 | `context.list_memories` / `context.create_memory` | `GET/POST /context/users/{user_id}/memories` |
| 记忆更新/删除 | `context.update_memory` / `context.delete_memory` | `PATCH/DELETE .../memories/{memory_id}` |
| 会话消息读取/清空 | `context.list_session_messages` / `context.delete_session_messages` | `GET/DELETE .../sessions/{session_id}/messages` |

这里 `context` 指 `client.context`。直接使用能力类时，构造签名分别为：

```python
from gateway_client import GatewayVectorStore, GatewayContextClient

vectors = GatewayVectorStore(base_url, vector_key, collection, timeout=120)
context = GatewayContextClient(context_key, base_url=base_url, timeout=15)
```
